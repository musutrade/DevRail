## Why

后端验证当前包含一个 147 秒级的巨型 API 集成流程，且大量 PostgreSQL 测试通过进程内全局锁串行执行；CI 还会重复承担冷启动编译和镜像构建成本，导致反馈周期过长，降低开发和修复效率。

## What Changes

- 将巨型 API 集成流程拆分为边界清晰、可独立运行的测试场景，保留必须串行的迁移和全局策略验证。
- 提供进程内只初始化一次的测试迁移夹具和统一连接配置，先消除无效 migration 检查；连接池复用仅在测试隔离证明安全后启用。
- 为数据库集成测试引入安全的测试级隔离策略，移除不必要的全局串行锁。
- 在确认数据隔离后启用受控测试并发，并增加耗时基准和回归门禁。
- 为 Rust 编译和 Docker 构建启用 CI 缓存，减少重复下载、编译和镜像层构建。
- 不改变生产运行时行为、API 契约、数据模型或权限语义。

## Capabilities

### New Capabilities

无。该变更只调整测试基础设施、验证编排和 CI 性能，不引入生产功能。

### Modified Capabilities

无。没有需要修改的生产行为契约，因此本 change 使用 `skip_specs: true`。

## Impact

影响 `backend` 测试夹具、数据库测试初始化、`cargo flow` 验证配置、GitHub Actions 缓存配置和测试报告。需要确保 PostgreSQL 测试在并发运行时仍满足组织/部门/所有者范围、幂等性、迁移一致性和敏感数据约束；失败时必须保留可诊断日志和现有门禁结果格式。
