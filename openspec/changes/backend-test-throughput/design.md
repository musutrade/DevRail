## Context

当前后端验证通过 `cargo flow` 顺序执行 format、Clippy、compile、tests 等步骤。Rust 单元测试本身会并发运行，但 PostgreSQL 集成测试普遍获取进程内 `DATABASE_TEST_LOCK`，因此数据库场景在单个测试进程内实际串行。`backend/tests/api_flow.rs` 还把认证、MFA、权限、组织和 DevRail API 场景集中在一个 2292 行测试中，最近基线为库测试 25.26 秒、API 流程 147.10 秒。

测试迁移现在可以在单个测试进程内只初始化一次。共享全局 `PgPool` 的实验会让跨 `await` 的长事务和并发子任务争用连接，导致 `PoolTimedOut`；因此迁移初始化和连接池所有权必须分离，直至 schema 或 worker 隔离证明共享边界安全。

## Goals / Non-Goals

**Goals:**

- 建立进程内只初始化一次迁移、统一配置的测试数据库夹具；未隔离测试继续使用独立并会归还的连接池。
- 将巨型 API 流程拆分为可独立运行的测试边界，避免不必要的跨场景状态依赖。
- 使用测试级 schema 或等价隔离保证并发测试互不污染，再启用受控并发。
- 保留需要验证全局数据库约束的少数串行场景，并为并发上限建立基准。
- 缩短本地和 CI 的重复编译、依赖下载及 Docker 构建时间。

**Non-Goals:**

- 不改变生产 API、业务状态机、权限、迁移语义或测试断言含义。
- 不在共享数据库和全局可变环境变量仍未隔离时引入 `cargo nextest` 或跨进程并发。
- 不通过减少测试数量、跳过 E2E、放宽审计或降低断言来换取速度。

## Decisions

1. **先拆分慢测试，再优化调度。** API 流程按认证/MFA、权限与组织、DevRail 资源边界拆分；每个场景使用唯一前缀和独立夹具，迁移/审计全局约束保留专门串行测试。相比只提高线程数，这能直接消除 147 秒单测试的长尾。
2. **迁移初始化与连接池所有权分离。** `test_pool` 共享迁移完成状态和连接配置，但未隔离测试仍创建并关闭自己的 `PgPool`；这样可避免跨 `await` 事务和并发子任务在共享池中发生 `PoolTimedOut`。只有 schema 或 worker 隔离通过验证后，才以隔离域为边界复用连接池。
3. **测试隔离优先使用 schema 级隔离。** 每个集成测试创建唯一 PostgreSQL schema，在连接建立后设置 `search_path`，并在测试结束清理；迁移由共享初始化阶段完成或按 schema 一次执行。若发现扩展、触发器或连接级对象无法安全按 schema 隔离，则退回每 worker 独立数据库，不允许静默共享。
4. **并发采用显式上限。** 第一阶段以 `--test-threads=4` 或等价配置运行，结合 PostgreSQL 最大连接数和 CI CPU 调整；基准显示稳定收益后才提高上限。所有涉及环境变量、固定端口、全局文件或全局迁移的测试仍归入串行组。
5. **验证编排保持结果可追溯。** `cargo flow` 继续生成现有日志和 `TEST_SUMMARY`，并把测试线程/隔离模式记录在报告元数据中；不并行执行会争用同一报告文件或测试服务的步骤，除非编排器先提供独立日志和服务生命周期。
6. **缓存只作用于 CI 构建层。** Rust toolchain action 使用依赖/目标缓存，Docker 使用 BuildKit GitHub Actions cache；缓存失效或命中错误不得改变测试结果，缓存配置失败时门禁仍明确失败而不是跳过验证。

## Risks / Trade-offs

- [隔离不完整导致并发测试互相污染] -> 为 schema、环境变量、临时目录和端口建立唯一命名；先运行重复/随机顺序测试，再逐步放开并发。
- [迁移和 schema 初始化抵消收益] -> 共享迁移版本快照，测量初始化耗时；只在 schema 真正需要时执行增量迁移。
- [并发过高使 PostgreSQL 或 Argon2 饱和] -> 以 CPU、连接池和数据库锁等待为指标，默认上限为 4，并支持 CI 环境覆盖。
- [拆分 API 流程改变隐含顺序] -> 每个测试显式创建所需用户/组织/角色，保留原有断言，使用失败重试和随机顺序验证独立性。
- [缓存携带错误产物] -> 使用锁文件、toolchain 和 Dockerfile 作为缓存键的一部分，并在命中后仍执行完整检查。
