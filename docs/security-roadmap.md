# 安全能力状态

本文件记录高权限认证的当前实现与仍由生产环境承担的控制。它不是合规认证，也不替代威胁建模、渗透测试或基础设施评审。

## 已实现：`super_admin` 多因素认证

- [x] 登录策略：密码校验后进入五分钟的一次性 MFA 挑战，验证完成前不创建认证会话；
- [x] 首次注册：强制注册 TOTP，并一次性签发 10 个恢复码；
- [x] 因子：支持 TOTP、WebAuthn 通行密钥和一次性恢复码；
- [x] 密钥保护：TOTP 使用 AES-256-GCM 加密，恢复码只保存 Argon2 哈希；
- [x] 服务端状态：MFA 挑战与 WebAuthn ceremony 保存在 PostgreSQL，过期或消费后不可复用；
- [x] 强制策略：所有 `super_admin` 必须完成 MFA，不允许通过记住设备、密码重置或管理 API 绕过；
- [x] 敏感操作：撤销通行密钥和重新生成恢复码需要当前密码与 TOTP；
- [x] 会话处置：恢复码使用、通行密钥撤销、恢复码重新生成和权限提升会撤销或失效既有会话；
- [x] 审计：记录注册、验证成功/失败、因子撤销、恢复码使用和策略变更，不记录密钥或验证码原文；
- [x] 契约与测试：迁移、API、Angular 安全页、OpenAPI、后端集成测试与 E2E 均已接入。

实现细节见 [架构说明](architecture.md)，生产配置与恢复流程见 [多因素认证运维](mfa-operations.md)。

## 生产责任

- 从密钥管理系统注入独立的 `MFA_ENCRYPTION_KEY`，禁止跨环境复用；
- 使用用户实际访问的 HTTPS 域名配置 `WEBAUTHN_RP_ID` 与 `WEBAUTHN_RP_ORIGIN`；
- 至少维护两个分别受控的超级管理员，并离线保存各自的恢复码；
- 上线前完成 TOTP、通行密钥、恢复码、撤销、重新生成、会话失效和审计查询演练；
- 为 MFA 加密密钥丢失、域名迁移和管理员设备丢失建立经审批的恢复流程；
- 定期复核超级管理员、通行密钥和恢复码保管人，结果纳入发布与审计证据。

## 后续增强

以下是按具体业务风险选择的增强项，不代表当前基线存在认证旁路：

- 为普通高权限角色提供可配置的强制 MFA 策略；
- 增加企业身份提供商 OIDC/SAML 与身份生命周期同步；
- 增加加密密钥版本和在线重加密能力，支持可演练的 `MFA_ENCRYPTION_KEY` 轮换；
- 为高风险操作引入双人复核、交易级签名或更细的 step-up 策略；
- 在独立环境执行定期渗透测试和 WebAuthn/MFA 滥用场景演练。
