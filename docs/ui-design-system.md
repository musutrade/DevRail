# UI 与 CSS 规范

本文档是 arc-admin 页面设计、实现与评审的统一基线。用户管理和权限目录定义了数据管理页的结构基准；部门、角色、权限分配、审计日志、账号安全和错误页遵循同一视觉语言，并针对各自内容采用响应式呈现。

## 规范来源

样式按以下优先级维护：

1. `frontend/src/styles/_tokens.scss`：设计语义的唯一基础，包括字体、间距、圆角、控制高度、动效、亮暗颜色和 Material M3 token 映射；
2. `frontend/src/styles.scss`：两个及以上页面复用的页面模式和组件样式；
3. 页面 `.scss`：只保留页面独有的布局、列宽或内容表现；
4. Angular Material 组件：通过 `--mat-sys-*` 语义变量适配，不在页面内穿透覆盖其内部实现。

新增颜色、尺寸或动效前，先确认现有 `--ui-*` 是否已经表达该语义。只有跨页面确实缺少新语义时才增加 token，并同时补齐亮色、暗色和必要的强制颜色表现。

## 页面结构

标准数据页使用以下层级：

```html
<section class="page">
  <header class="page-header">
    <div>
      <h1>页面标题</h1>
      <p>一句话说明页面用途</p>
    </div>
    <div class="header-actions">主要操作</div>
  </header>

  <div class="filter-bar">搜索、筛选和结果数</div>
  <div class="table-card">表格、加载、错误或空状态</div>
  <section class="stats-grid">可选统计摘要</section>
</section>
```

- 每个页面只有一个可感知的 `h1`，标题与说明使用 `.page-header`；
- 页面内容最大宽度为 1200px，桌面内边距 24px，窄屏由全局样式收紧到 16px；
- 主要操作放在右侧 `.header-actions`，窄屏允许自然换行；
- 统计摘要位于主表之后，使用统一 `.stats-grid` 和 `.stat-card`，不为单页创建另一套卡片视觉；
- 应用壳层提供唯一的 `main` landmark，页面组件不得再嵌套 `<main>`。

## 共享样式

| 模式       | 共享类                                                                                                      | 约束                                                   |
| ---------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 页面与标题 | `.page`、`.page-header`、`.header-actions`                                                                  | 页面级结构不得重复实现宽度和间距                       |
| 操作按钮   | `.btn-primary`、`.btn-outline`、`.row-btn`                                                                  | 主操作每个区域通常不超过一个；图标按钮必须有可访问名称 |
| 筛选       | `.filter-bar`、`.filter-search`、`.filter-right`、`.filter-select-group`、`.filter-select`、`.filter-count` | 搜索有标签，结果数随筛选更新                           |
| 数据表     | `.table-card`、`.table-scroll`、`.data-table`、`.table-footer`                                              | 使用真实 `table` 语义和唯一 `caption`                  |
| 状态       | `.status-badge`、`.status-dot`、`.st-active`、`.st-suspended`                                               | 颜色与文字同时表达状态，不只依赖色点                   |
| 页面状态   | `.loading-wrap`、`.empty-state`                                                                             | 加载、错误、空数据必须互斥且有明确文案                 |
| 统计摘要   | `.stats-grid`、`.stat-card`、`.stat-label`、`.stat-value-row`                                               | 复用同一密度、边框、阴影和数字层级                     |

跨页面重复的类应提升到全局样式；只被单页使用、且包含该页业务语义的样式保留在组件内。不要用复制粘贴制造视觉相同但维护分叉的实现。

## Token 与 CSS 规则

- 间距使用 `--ui-space-*` 的 4px 阶梯；常用页面间距为 16px、20px、24px 和 32px；
- 控件高度使用 `--ui-control-sm/md/lg`，移动端可触控目标不小于 40px；
- 小控件、表单和卡片分别使用现有 `--ui-radius-*`，状态胶囊只使用 `--ui-radius-pill`；
- 文本、表面、边框、状态和遮罩全部使用 `--ui-color-*`，页面 SCSS 不写十六进制业务颜色；
- 层级使用 `--ui-shadow-sm/md/lg`，数据表与基础卡片优先使用边框和轻阴影；
- 交互过渡使用 `--ui-duration-*` 和 `--ui-ease-*`，不要用 `transition: all`；
- 选择器保持组件可读性，避免无必要的 `!important`、深层后代选择器和高 specificity；
- 禁止移除焦点轮廓。需要自定义时使用 `--ui-focus-ring` 并保证键盘可见；
- 不以固定高度裁切动态文案，不依赖横向页面滚动承载主要操作。

## 表格与移动端

桌面数据页优先使用语义表格：

- 每张表只提供一个描述内容的 `<caption>`；可视觉隐藏，但不能重复；
- 表头使用 `scope="col"`，行操作列置于末尾并保持足够宽度；
- 加载时设置 `aria-busy`，空状态和错误状态替换数据行或卡片内容；
- 状态、角色和权限等含义必须有文字，不把 tooltip 当作唯一信息来源。

响应式策略按信息密度选择：

- 常规表格在自身 `.table-scroll` 内横向滚动，不让整个页面溢出；
- 权限分配等必须持续操作末列的表格，在窄屏固定操作列，并隐藏可从详情获得的次要列；
- 审计日志字段多且内容长，`760px` 以下切换为卡片列表，按“动作与时间、操作者、目标、追踪号、详情”顺序展示；
- 筛选栏在窄屏纵向排列，输入和选择器占满可用宽度；
- 不能仅靠缩小字体把桌面表格塞进手机。

应用壳层在 `768px` 以下切换移动导航，在 `1024px` 以下收窄侧栏。页面可以根据内容使用更小断点，但必须同时在 Desktop Chrome 和 Pixel 7 视口验证。

## 交互状态

每个异步页面都应覆盖四种可见状态：

1. 加载：显示进度和说明，容器设置 `aria-busy="true"`；
2. 成功：显示数据，操作完成后就地更新或重新加载；
3. 空数据：说明当前没有什么，并在用户可解决时提供下一步；
4. 失败：保留页面上下文，显示简洁错误与“重试”，不能留下空白页面。

提交按钮在进行中禁用并显示动作状态；成功反馈使用 `role="status"`，错误使用 `role="alert"`。危险操作必须说明对象和影响，并要求明确确认。对话框在移动端距离视口边缘至少 8px，关闭后焦点返回触发控件。

## 无障碍

- 保持应用级“跳到主要内容”链接和唯一 `main` landmark；
- 图标按钮、复制按钮、菜单开关和主题开关必须提供准确的可访问名称；
- 移动菜单维护 `aria-expanded`，关闭后把焦点还给菜单按钮；
- 表单控件有可见标签或等价的程序化名称，错误信息与控件关联；
- 颜色不作为唯一状态表达，文本与背景在亮暗主题下都保持可读；
- 动画在 `prefers-reduced-motion: reduce` 下关闭；
- Windows 强制颜色模式下保留焦点、边框与状态结构。

## 评审与验证

实现前先搜索全局模式，避免重复 CSS。完成后至少执行：

```bash
cd frontend
npm run lint
npm run format:check
npm run test:ci
npm run build
VISUAL_REVIEW=1 npm run e2e -- --project=chromium --project=mobile-chromium
```

视觉复核逐页检查：

- 标题、说明、主要操作、过滤栏、表格和统计卡的顺序是否一致；
- 桌面和移动端是否没有页面级横向溢出、裁切或遮挡；
- 加载、空、失败、禁用和提交中状态是否可见；
- 键盘焦点、菜单返回焦点、对话框尺寸和 snackbar 位置是否正确；
- 亮色、暗色、减少动效和强制颜色是否仍能理解；
- 表格 caption、landmark、按钮名称和状态反馈是否符合语义；
- 新样式是否只使用语义 token，且没有复制已有共享类。

PR 前从仓库根执行 `cargo flow verify --all`，以相同门禁覆盖前端、后端、工作流、E2E 与生产构建。
