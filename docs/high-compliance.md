# 高合规部署基线

`deployment/.env.compliance.example` 是面向高审计要求项目的配置起点，不构成等保、ISO 27001、SOC 2 或行业法规认证。项目立项时必须根据数据分类、司法辖区、合同和威胁模型重新评审。

## 使用方式

将示例中的值合并到受保护的 `deployment/.env.production`，不要直接把示例作为生产密钥文件。它缩短会话、限制并发会话、把审计保留示例提高到 2555 天，并启用全量父级采样的 OTLP 配置。`OTEL_EXPORTER_OTLP_HEADERS` 由密钥管理系统在部署时注入。

## 必须补齐的控制

- 按[多因素认证运维](mfa-operations.md)管理加密密钥、WebAuthn RP 配置和恢复演练；MFA 完成不等同于任何合规认证。
- 数据库迁移账号、应用账号、只读分析账号和备份账号分离；应用账号不是表所有者或 PostgreSQL 超级用户。
- 审计归档上传到跨账号、启用对象锁定和保留策略的存储，并按季度执行校验与恢复演练。
- TLS 私钥、数据库密码、OTLP Header、Grafana 联系点和备份凭据全部由外部密钥系统注入并定期轮换。
- 对日志、指标和 trace 建立字段白名单与数据分类，禁止采集认证凭据、请求正文和不必要的个人信息。
- 将 CodeQL、依赖审计、镜像扫描、SBOM、备份恢复、告警送达和权限复核结果纳入发布证据。

本地 Tempo 的 72 小时数据和数据库触发器都只是纵深防御：数据库所有者可以停用触发器，宿主机管理员也可以修改本地卷。最终证据必须落在权限独立、不可变并有访问审计的外部系统中。
