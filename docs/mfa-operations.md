# 多因素认证运维

`super_admin` 必须在密码校验后完成多因素认证。首次登录会强制注册 TOTP，并一次性签发 10 个恢复码；未完成前后端不会创建认证会话。完成注册后可在“账户菜单 → 账号安全”添加通行密钥、重新生成恢复码或撤销通行密钥。

## 生产配置

生产环境必须由密钥系统注入以下变量：

| 变量 | 要求 |
| --- | --- |
| `MFA_ENCRYPTION_KEY` | 随机 32 字节的 Base64 值，用于 AES-256-GCM 加密 TOTP 密钥 |
| `WEBAUTHN_RP_ID` | 稳定的 relying party 域名，通常与 `APP_HOST` 相同 |
| `WEBAUTHN_RP_ORIGIN` | 用户实际访问的 HTTPS origin，包含协议和非默认端口 |
| `WEBAUTHN_RP_NAME` | 身份验证器向用户显示的站点名称 |

可用 `openssl rand -base64 32` 生成新环境的加密密钥，但不得把输出写入版本库、Compose 模板、工单或普通日志。`MFA_ENCRYPTION_KEY` 丢失后现有 TOTP 密钥无法恢复；轮换前必须实现并演练受控重加密，不能直接替换环境变量。`WEBAUTHN_RP_ID` 会绑定到已注册凭据，域名迁移前必须设计凭据迁移或重新注册窗口。

## 恢复与撤销

- 恢复码只保存 Argon2 哈希，每个码仅可使用一次；使用后立即撤销该用户的全部旧会话。
- 重新生成恢复码需要当前密码和 TOTP，生成后旧恢复码和全部会话立即失效。
- 撤销通行密钥需要当前密码和 TOTP，完成后全部会话立即失效。
- `super_admin` 的 TOTP 不允许通过管理 API 停用。至少维护两个分别受控的超级管理员，每个账号都应保存离线恢复码，避免单个设备丢失造成无法恢复。

通行密钥注册和认证挑战只在 PostgreSQL 服务端保存，五分钟后过期且只能消费一次。二次验证连续失败五次后当前挑战失效；用户必须重新从密码阶段开始。

## 验收

上线前在实际生产域名完成以下演练：首次 TOTP 注册、TOTP 登录、通行密钥注册与登录、恢复码登录、通行密钥撤销、恢复码重新生成、会话立即失效和对应审计事件查询。不得使用测试 origin 或复制其他环境的 MFA 加密密钥。
